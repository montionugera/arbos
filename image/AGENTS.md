# Arbos project box

Your project folder is your working directory (`/work/<project-id>`; one box holds every project of the user, one folder each); you have full permission here (the box is the boundary). Stay inside your project folder. Search the Project's history and memory before asking (MCP server `arbos`: `history_search`, `history_read`, `read_thread`, `memory_search`, `memory_read`). Keep big data in variables or files and print slices; outputs over 4,000 characters become handles (`peek`). Browser: `agent-browser open <url>`, `snapshot -i`, `click @e1`, `screenshot out.png`. Provider keys and the Daytona key are not in this box; do not look for them. There is no tool-call or short wall-clock cap on your turn: keep going until the work is done. Long or research-heavy work still prefers a dedicated subagent when the main agent routes `new`. Subagents end their turn with the return-contract JSON block.

## Unknown services, APIs and tools

The box has open network access and `web_search(query)` / `web_fetch(url)` on the `arbos` MCP server. When a service, API, CLI or library is new to you, or a call fails (not found, 404, unknown endpoint), research it before anything else: search the vendor's site for its API reference, read the docs or the OpenAPI/Swagger spec (`/openapi.json`, `/swagger.json`, `/docs`, `/redoc`, `/llms.txt`), check package registries (`pip`, `npm`, `cargo`), install the official SDK or CLI (`pip install …`, `uv tool install …`, `npm i -g …`, `cargo install …`, a release binary; `python3`, `pip`, `uv`, `npm`, `gh` are on PATH and installs land in your own home) and read its `--help` or source for the real endpoints and auth. Guessing URLs is not research; asking the user for docs or endpoints is never the answer. Escalate to the user only for a genuine blocker (missing credential or account, a paid decision or spend confirmation, or an ambiguous intent) — never for "I don't know the API". When you do stop, say what you verified and the open question. Anything that charges the user beyond what they asked needs their go-ahead first, with the chosen option and its price.

Secret notes: each secret the owner stored comes with their note (`use_notes` in `secrets_list`, comments in your shell's secrets.env); the note is the policy for that key — for `egress` and for any CLI, SDK or script that reads the real `$NAME`. Spending guidance in it binds you: a limit ("may spend up to $X without asking") lets you proceed within it and no further; "confirm before charging" or "read-only" means ask first or never charge, whatever the brief says. A note without spending guidance leaves the money rule above in force. Never pass a confirmation-skipping flag (`--yes`, `-y`, `--force`, `--no-confirm` and the like) to a command that charges unless the note allows that spend.

## Producing files

Files for the user (slides, documents, spreadsheets, PDFs, images, video) go under `out/` in your project folder, then `deliver_file(path, title?)` (MCP `arbos`) shows them in the chat as a download card. `/opt/prime-venv/bin/python` has python-pptx, python-docx, openpyxl, Pillow and reportlab; `ffmpeg` is on PATH. `generate_image(prompt, size?)` makes a picture through the relay and delivers it. Prime subagents: `await arbos_deliver_file.run("out/report.pptx", title="Q3 deck")` (relative paths resolve in the project folder).
