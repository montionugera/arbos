# Decisions

- 2026-10-11: The import commit does not publish a GitHub Release. Releases start when the binary is branded Arbos and actually launches. A signed DMG of unmodified zeron would ship the wrong product.
- 2026-10-11: This product key is vault item ENGY_2, because it is the key Jacob named.
- 2026-10-11: Balance stays unread until a real route exists.
- 2026-10-11: The fx binary is still named `fx` this increment so the upstream smoke test and subtree pull stay intact.
- 2026-10-11: The GitHub description is "Arbos is a coding-agent app being rebuilt on fx and zeron. The harness speaks engy.ai." Root CI runs fx's 2 ms startup budget and the Linux binary-size watch at the upstream thresholds (2 ms raw mean, 52,429 byte warning).
- 2026-10-11: A missing profile home does not fail `fx ask`. Full access stays the default when the client sets no mode. The one-time full-access warning and its acknowledgment save are skipped when no home is available.
- 2026-10-11: The profile usage ledger uses the session home override, then `ARBOS_FX_HOME`, then `HOME`.
- 2026-10-11: Root CI runs a filtered Zig check for engy defaults, `reasoning_effort`, home selection, and the ask tests. The full `zig build test` suite is not a required check. Six failures in that suite already fail on `0f998ae8`, before the engy commit.
- 2026-10-11: The Rust package stays `zeron` and the binary stays `zeron`. Renaming either one touches the whole tree. The window title and the about string say Arbos.
- 2026-10-11: The visible harness is fx (`fx acp`), wire id `arbos-fx`. Other ACP specs and the native Claude, Codex, and Cursor drivers stay compiled in. `harness-prefs.json` field `show_all` defaults to false and hides them from `ListHarnesses`. Mock stays in that list. The UI already hides Mock unless `ZERON_HARNESS=mock`.
- 2026-10-11: The Pi and opencode driver modules are deleted. `HarnessId::Pi` and `HarnessId::Opencode` stay so old chat JSON still parses. They are not registered.
- 2026-10-11: Hosted sync is not in this build. The process does not construct an edge client, does not read a WorkOS client id, and does not dial zeron.sh. The edge and sync source files stay on disk. There is no flag that turns the dial back on.
- 2026-10-11: `ENGY_API_KEY` is passed to the fx child. It is not written into the project, a settings file, or a log. Linux stores it in a mode 600 file. macOS stores it in the login keychain under the service `arbos`.
- 2026-10-11: A chat's fx files go under `.arbos/agents/<id>/fx`. When a chat has no home of its own, the process uses `ARBOS_FX_HOME` if that variable is set, and otherwise `~/.local/share/arbos/fx`.
- 2026-10-11: The fx binary is the first `fx` on `PATH`. If PATH has none, the app uses `fx/zig-out/bin/fx` from this repo. `FX_EXECUTABLE` still overrides both.
- 2026-10-11: The app starts in dark appearance. A settings file with no `appearance` key loads dark.
- 2026-10-11: A project is `<folder>/.arbos/`. That directory is its own git repo. The app commits it after a turn. fx files for a chat go under `.arbos/agents/<id>/fx`.
- 2026-10-11: A project fx session gets one MCP server named `arbos`. Main gets `agents.spawn`, `agents.send`, `agents.list`, `agents.result`, `context.read`, and `context.write`. Every other chat in the project gets `context.read` and `context.write` only. fx calls those tools as `mcp_arbos_<name>` after `mcp_select_tool`.
- 2026-10-11: `agents.spawn` accepts `machine` `local` or the name of a registered install. `worktree: true` is an error.
- 2026-10-11: When a worker's turn ends, the engine wakes Main. If Main is mid-turn, the wake is a steer with `_meta.fx.steer` and `_meta.fx.wake`. Otherwise it is a new prompt with `_meta.fx.wake`. The transcript stores that line as a system message that begins `Worked ·`, not as a user bubble.
- 2026-10-11: Main's transcript uses the compact fold: one `Worked for` line, the reply, and no tool cards. Every other chat keeps the classic transcript.
- 2026-10-11: A file in `.arbos/subscriptions/` is `timer`, `github_pr`, `github_ci`, or `slack`. When one is due, the engine prompts Main with no user message. The transcript stores that line as a system message that begins `Worked ·`. Fire times stay in `.arbos/runtime/`.
- 2026-10-11: Provider keys stay out of `.arbos` and out of settings files. macOS stores them in the login keychain under the service `arbos`. Linux stores them in a mode 600 file, `~/.local/share/arbos/secrets/<name>` unless `ARBOS_SECRETS_DIR` points somewhere else outside `.arbos`. The fx child receives the value only as an environment variable. Settings → Keys writes the fx connection (the variable name, never the value) and that store.
- 2026-10-11: The update checker reads `manifest.json` from the GitHub Release tagged `edge`. The advisory strip opens `https://github.com/unarbos/arbos/releases`. `.github/workflows/linux-tarball.yml` may publish a Linux tarball after CI on `main` is green. It does not upload a DMG or any Mac artifact. Developer ID signing stays on Jacob's Mac.
- 2026-10-11: Slack uses fx's own connector (`fx slack install`, callback `https://fx.sh/api/slack/oauth/callback`). Reading the install config did not ask for a Vercel login. A slack subscription does not wake Main until a workspace installation exists.
- 2026-10-11: A project's home is a machine name in `project.toml`. `arbos project move <name> --to <machine>` sets that name, copies `.arbos` over SSH, and asks the home engine to adopt the folder. The rail shows the home under the project icon. Timers for that project run on the home engine. Closing the local window does not stop that engine.
- 2026-10-11: Remote identity is Cloudflare Access. The headless engine binds `127.0.0.1` only. A tunnel publishes it. Clients send the Access service token from the mode 600 secrets file. SSH is the fallback used to copy the project tree.
- 2026-10-11: Any install can register as a worker. `agents.spawn` accepts `machine` `local` or the name of a registered install. The MacBook `2a05bc55-df5b-4687-8b45-ac94702d71d0` was offline, so the proof used a second local install registered under that same name.
- 2026-10-11: The published Linux artifact is `arbos-<version>-linux-<arch>.tar.gz`. The update client requests that name. The tarball contains the binary as `zeron` and a copy named `arbos`. The Rust package stays `zeron`. The workflow does not upload a DMG.
- 2026-10-11: The version line a person sees is `Arbos 0.2.111`. The clap command name is `Arbos`, so `zeron --version` prints that line. The Rust package and the on-disk binary stay `zeron`. Renaming the crate would touch the whole tree. `core_version()` returns the same words. The phone screen uses the same words.
- 2026-10-11: The phone speaks the desktop RPC. `GET /v1/rpc` on the home engine port upgrades to the same websocket the desktop uses. Localhost IPC still rejects an `Origin` header. The phone client crate is `zeron-phone`. `app/crates/mobile` stays the voice and orb core and is not linked. This slice has no voice and no calls.
- 2026-10-11: The iPhone archive is built on a GitHub-hosted macOS runner. The MacBook worker `2a05bc55-df5b-4687-8b45-ac94702d71d0` was offline. `.github/workflows/ios.yml` uploads to TestFlight when the Apple secrets are present. A missing private key or an Apple rejection does not fail the job, so Linux CI stays green. The workflow file is not `release.yml`.
